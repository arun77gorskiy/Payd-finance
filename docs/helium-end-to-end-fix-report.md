## 1. ROOT CAUSES IDENTIFIED (3 BUGS)

### Bug #1 — Schema mismatch in persistence
- **File:** `public/data/intelligence/projects/helium.json` (V2 deep profile, generated by `helium_deep_enrichment.js`)
- **Problem:** The deep-enrichment script saves to a per-project file, but the frontend never reads from that path. The V2 deep-profile envelope uses `metrics.market.<field>.value`, whereas the renderer's flat path is `metrics.<field>`.
- **Effect:** Even if the file were loaded, the V1 renderer would receive `metrics.market_cap_usd = undefined` because the actual value lives at `metrics.market.market_cap_usd.value`.

### Bug #2 — `loadEnrichedData()` does not expand `data.projects` array
- **File:** `public/js/intelligence/intelligence-data.js`, function `loadEnrichedData()` (line 282)
- **Problem:** The loader did:
  ```js
  Object.keys(data).forEach(id => map.set(id, data[id]));
  ```
  But `projects_enriched.json` has shape `{ projects: [...] }`, so the resulting Map contained a single key `'projects'` whose value was the whole array. `enrichedMap.get('helium')` therefore returned `undefined` for every project.
- **Effect:** Even the few identity fields that *did* exist in `projects_enriched.json[helium]` (no market/github/ai data, but at least identifiers) were never injected into the V1 object.

### Bug #3 — Stale-data guard in v2-render
- **File:** `public/js/intelligence/intelligence-v2-render.js`, line 70
- **Problem:** `VERIFICATION_MAX_AGE_MS = 30 days`, but every project in `projects.json` had `lastVerifiedAt: "2026-07-16"`. As of 2026-09-01 that is 47 days, so `isProjectVerified()` returned `false` for all 349 projects.
- **Effect:** The dashboard rendered zero projects even after Bugs #1 and #2 were fixed.
