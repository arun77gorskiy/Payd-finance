# Подготовка подключения PAYD Intelligence

Проверено 18 октября 2026 года. Клиент API и адаптер canonical runtime подготовлены; основной сайт пока использует прежний поток данных. Включение на сайте и продвижение backend в production не выполнялись.

## Полученные живые ответы

Пользователь открыл API в своём авторизованном браузере и передал два полных тела ответа. SAFE: `LIVE`, `coinmarketcap`, `PRO_API`, provider ID `21585`, положительная цена `0.100884049818316`, provider timestamp `2026-10-18T18:04:54.000Z`. Ceramic: `UNKNOWN_MAPPING`, `market: null`, `provider_id: null`. Оба ожидаемых случая прошли проверку структуры; ответы сохранены в `reports/stage5c-public-market-observations-20261018.json`.

Соседний Health в `18:04:23.236Z` показывает commit `e82508e447c1fc869d5d84ab15141a76c03c3ff7` и ожидаемый SHA каталога. Рыночные ответы сами не содержат версию; это сопоставление по соседнему Health, а не встроенная атрибуция каждого ответа. HTTP status/headers не передавались. Из этих двух тел нельзя выводить, что проверены кеш, MiniMax CORS или все 279 котировок. Полный аудит каталога для следующего перехода не требуется.

## Готовый адаптер карточек

`code/client/market/payd_market_binding.js` связывает проверенный клиент с результатом существующего `PAYD_INTEL.Canonical.build`. Он остаётся инертным с выключенным клиентом. При явном включении очищает исторические `market`, шесть рыночных значений `_display`, ATH/ATL/timestamp и memoized `_v1_view` **до первого render**. Обновляет общие для всех секторов объекты, добавляет отдельные market status/hint/timestamp/symbol/provider ID и сохраняет TVL, AI, сектора и identity-классификацию.

`refresh(visibleCanonicalIds)` запрашивает только выбранные canonical ID. Одна очередь на адаптер ограничивает одновременные операции четырьмя даже при перекрывающихся вызовах. Устаревший ответ не перезаписывает более новый; `dispose()` очищает цены, отменяет очередь и игнорирует поздние ответы. Маленькие ненулевые значения не округляются до `$0.000000`.

**105/105 offline checks PASS**: 48 core, 15 smoke, 42 Node tests. Семь новых проверок используют неизменённый normalizer опубликованного сайта в Node VM с синтетическими проектами, настоящий клиент и два переданных тела API; проверяют поля отображения, очистку V1-кеша, согласованность секторов, общую очередь, порядок ответов, dispose и ошибки. Это проверка границы данных, не отрисованного браузерного интерфейса. Пример вызовов и точные обязанности страницы — в `code/client/market/README.md`.

HTML/loader, фактический renderer и CoinGecko pipeline основного сайта ещё не изменены. Сам адаптер не добавляет market badge в DOM, не устраняет legacy fallback до canonical readiness и не переносит исправленные символы/классификацию в frontend identity JSON. Это конкретные изменения следующего пакета для актуального проекта MiniMax; старую GitHub-ветку нельзя считать полной копией его текущих исходников.

## Найден основной сайт и его исходники

Основной опубликованный сайт: https://hksp6x4kqtxs.space.mcode.io/. Прямое чтение вернуло HTTP 200 и заголовок `Payd_Finance | AI Crypto Trading & Education`. Это адрес из `deploy_url.txt` ветки [payd-v2-step4-boot-optimization](https://github.com/arun77gorskiy/Payd-finance/tree/payd-v2-step4-boot-optimization), commit `e96342141127118bdae89d8073a040bc56045b14`.

Ветка `main` содержит только начальный служебный файл, ветка Stage 5C — backend. Полный старый фронтенд находится в указанной отдельной ветке. Она не является полной копией текущего опубликованного сайта: три полученных JS-файла совпадают байт в байт, но текущий HTML отличается, а `canonical-normalizer.js` отсутствует в дереве ветки. Поэтому нельзя заменять весь сайт содержимым этой ветки. Хеши и результаты чтения сохранены в `reports/stage5c-frontend-boundary-20261018.json`.

## Где проходит текущий поток данных

| Файл опубликованного сайта | Роль | Изменение при последующем включении |
|---|---|---|
| `js/intelligence/intelligence-data.js` | `refreshLiveMarketData` обращается к CoinGecko; при ошибке сохраняется снимок | Заменить именно рыночный overlay вызовом PAYD API по точному canonical ID; исключить fallback для этих полей |
| `js/intelligence/intelligence-data-preloader.js` | Строит canonical runtime из `projects_enriched.json` до первого отображения | В режиме PAYD API сначала очищать прежние рыночные поля; загружать видимые карточки, не блокируя запуск всей страницы |
| `js/intelligence/canonical-normalizer.js` | Хранит `market` и вычисляет `_display` один раз | Обновлять оба представления после ответа; старый `_display` не должен оставаться после ошибки |
| `js/intelligence/intelligence-v2-render.js` | Карточка читает `_display`, показывает прежний identity-status | Добавить отдельный `market_status`, timestamp и подсказку; не заменять identity-status рыночным статусом |
| `js/intelligence/config/data-provider.config.js` из архивной ветки | `ACTIVE_PROVIDER = 'local-json'` управляет всем хранилищем | Не переключать глобально на `api`: этот общий ApiDataProvider пока заглушка и затрагивает исследования, проекты и другие данные |

Это разделение объясняет отсутствие видимого результата: подготовленный CMC backend ещё не участвует в потоке опубликованного сайта.

## Готовый клиент

`code/client/market/payd_market_client.js` — обычный browser script, также импортируемый в Node для проверки. Регистрирует `PAYD_INTEL.PaydMarketClient`; загрузка файла не запускает запросов. `enabled` по умолчанию выключен, и этот файл нигде не добавлен в действующие HTML/loader сайта.

Пример подготовки, не включающий соединение:

```js
const client = PAYD_INTEL.PaydMarketClient.createClient({
  enabled: false,
  baseUrl: approvedApiOrigin,
  records: reviewedTokenIndex.records,
});
const envelope = await client.getMarket(project.id);
const view = PAYD_INTEL.PaydMarketClient.toMarketView(envelope);
```

При разрешённом включении `records` должны происходить из того же проверенного Stage 5C каталога, что используется API: SHA-256 `30299813414d75d1e55579660a3ee23eb1f8d15e7cb4d732db20172e3c357ed0`, 354 записи. Не подставлять старые CMC ID из frontend JSON: клиент сверяет ID и символ ответа с этим каталогом.

Клиент запрашивает только `GET /api/intelligence/market?id=<canonical-id>` на заданном PAYD origin. Он не ищет по тикеру, не обращается к CMC/CoinGecko, не принимает ключи, не пишет в localStorage. Для LIVE/PARTIAL сверяет canonical ID, provider ID, символ, provider `coinmarketcap`, режим `PRO_API`, числовые типы и положительную цену. Все 12 полей нормализованного контракта копируются без округления; `0` и `null` различаются. Timestamp сохраняется для отображения давности, автоматическая сертификация свежести не выполняется.

Ошибки, карантин и отсутствие привязки дают пустое представление рынка. `toMarketView` следует применять к результату клиента и заменять им рыночные поля целиком; слияние со старым снимком запрещено. UI форматирует `null` как `—`, показывает `view.status` и `view.hint`. TVL, исследования, AI scores и identity-status не относятся к этому рыночному контракту.

Запросы имеют предел ожидания 8 секунд, включая чтение тела. Одновременные запросы одного ID объединяются; завершённый ответ в клиенте не кешируется, поэтому после ошибки не возвращается прежний LIVE. API/CDN сохраняют собственную существующую политику кеша.

## Обнаруженная граница доступа

Прямой запрос `/api/healthz` Stage 5C Preview получил **HTTP 302 на Vercel SSO**, тело `Protected by Vercel Authentication`, `Cache-Control: no-store`. Это ответ защиты платформы, не результат функции API. Ранее подключение Vercel возвращало 403 для команды проекта; CLI недоступен. Повторный такой запрос не проверит API.

Клиент использует `credentials: 'omit'` и не следует redirects. Защищённый Preview нельзя просто назначить публичному сайту: посетители не имеют авторизации Vercel. Для проверки из авторизованного браузера нужна отдельная проверка в существующей сессии; она не докажет доступность API для всех посетителей.

Кроме того, исходный CORS allow-list backend **не содержит** `https://hksp6x4kqtxs.space.mcode.io`. Фактическое значение `PAYD_ALLOWED_ORIGINS` в Preview прочитать не удалось, поэтому текущий runtime CORS неизвестен. Перед включением нужен точный frontend origin в allow-list и проверка настоящего браузерного GET/OPTIONS. Доступ к Preview и CORS — разные условия.

## Конкретный следующий переход

Подготовленное изменение можно применить к актуальному исходнику MiniMax после проверки доступа: добавить клиент, использовать отдельный выключенный по умолчанию market flag, заменить CoinGecko overlay, обновлять `market` и `_display`, загружать видимые canonical ID с ограниченной параллельностью и отображать ошибки без снимка. Начать с нескольких видимых карточек, затем проверить навигацию и повторный запрос. Слепой запрос всех 354 записей при старте страницы не нужен.

Для публичного включения также нужен развёрнутый доступный backend на проверенной версии. Production alias всё ещё относится к начальной ветке `main`; продвижение Stage 5C и включение frontend требуют отдельного решения. Полный повтор аудита токенов не решает ни одну из этих двух границ.

## Доказательства проверки

Восемь проверок клиента покрывают отключённое состояние, browser registration, семь исторически наблюдавшихся котировок, неправильную идентичность/KEYLESS, точные canonical ID, сетевые/HTML/HTTP ошибки, timeout/coalescing и очистку старого рынка. Существующая локальная HTTP-проверка расширена вызовами настоящего клиента через реальный market handler: семь записей передаются точно, все 75 заблокированных возвращают пустые поля, дополнительных обращений к provider нет.

Эти проверки используют предоставленный ранее capture и локальные fixtures. Они не являются свежим обращением к CMC, браузерной проверкой CORS на MiniMax или доказательством живого API за Vercel Authentication.
